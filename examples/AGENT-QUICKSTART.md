# DocuHand — 60-second quickstart for AI agents
#
# This file is written FOR AN AI AGENT. If you were pointed at it, here is
# exactly what to do.
#
# ── WHAT THIS IS ────────────────────────────────────────────────────────
# DocuHand is a Model Context Protocol (MCP) server that drives real
# Microsoft Word / WPS Office on Windows. It can read legacy .doc binaries,
# convert them, extract tables, fill templates, and export PDF - by
# automating the actual word processor, not by parsing XML.
#
# ── STEP 1: CHECK PRECONDITIONS (do this before anything else) ──────────
#   - OS must be Windows. This does not work on Linux or macOS.
#   - Python must be 3.12 or newer.
#   - Either Microsoft Word OR WPS Office must be installed.
#   If any of these fail, stop and tell the user which one failed.
#   Do NOT attempt to install Office yourself.
#
# ── STEP 2: IS THE MCP SERVER ALREADY CONNECTED? ────────────────────────
#   Try listing the docuhand tools. If you can call `inspect_document`,
#   the server is connected - skip to STEP 4.
#   If not, show the user this config and ask them to add it to their MCP
#   client settings, then restart the client:
#
#     {
#       "mcpServers": {
#         "docuhand": {
#           "command": "uvx",
#           "args": ["docuhand", "serve"]
#         }
#       }
#     }
#
#   `uvx` needs no permanent install. If the user prefers:
#     pip install docuhand
#   and then use "command": "docuhand" instead.
#
# ── STEP 3: GET A TEST FILE ─────────────────────────────────────────────
#   Ask the user for a .doc/.docx file, OR download the synthetic demo:
#     https://raw.githubusercontent.com/H-Mon/docuhand/main/examples/demo-files/DocuHand_Demo.doc
#   The demo contains one table (4 rows x 4 columns) and one bookmark
#   named "DemoBookmark". It is generated by scripts/make_demo_docs.py and
#   contains no real or personal data.
#
# ── STEP 4: RUN THIS SEQUENCE ───────────────────────────────────────────
#   Call the tools in this order and report each result in plain language:
#
#   1. inspect_document(path=DEMO)
#      -> report: real format (detected vs extension), page count,
#         table count, whether it is locked/encrypted
#
#   2. extract_content(path=DEMO, what="tables")
#      -> report: the JSON grid. This is the headline result - it proves the
#         tool can read tables out of a legacy binary format.
#
#   3. convert_documents(directory=DIR_OF_DEMO, to_format="docx")
#      -> report: how many converted, how many failed
#
#   4. fill_template(template_path=THE_NEW_DOCX,
#                    data={"DemoBookmark": "Filled by an AI agent."},
#                    mode="bookmarks")
#      -> report: filled_keys and missing_keys
#
#   NEVER modify or delete the original file. convert_documents and
#   fill_template write new files next to the source.
#
# ── STEP 5: REPORT ───────────────────────────────────────────────────────
#   Tell the user what each step returned. If a step fails, the response is
#   {"ok": false, "error": {error_code, human_message, llm_hint, details}}.
#   Read error.llm_hint - it tells you how to fix the call (bad path, wrong
#   argument, file outside the allowlist...). Errors are structured data,
#   not stack traces.
#
# ── IF SOMETHING FAILS ───────────────────────────────────────────────────
#   - "Word not installed" / COM error: the machine may have only WPS.
#     DocuHand falls back to WPS automatically. If both fail, the user
#     needs to install Word or WPS.
#   - Modal dialog blocking: DocuHand pre-checks files for encryption and
#     corruption before opening them, so this should not happen. If it does,
#     the file is likely password-protected.
#   - Timeout: the COM call exceeded its budget. Raise DOCUHAND_COM_TIMEOUT
#     in the server's env config.
#
# Full docs: https://github.com/H-Mon/docuhand
# Pitfalls (the interesting part): https://github.com/H-Mon/docuhand/blob/main/docs/pitfalls.md
